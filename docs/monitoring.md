# 监控与日志

启动引擎后，切换到 **监控** 页可看到实时进度。监控页是只读的 —— 不能从这里改任何配置或触发操作。

![监控页](images/monitor.png)

---

## 1. 实时监控（5 个统计卡片）

| 卡片 | 颜色 | 含义 |
|---|---|---|
| **待发送** | 灰底 | 当前 `status = pending` 的收件人数。引擎启动后会持续下降 |
| **验证中** | 蓝底 | 已发出但还在等送达验证的批次数。送达后转移到 "已送达"，超时转移到 "未送达" |
| **今日已发** | 橙底 | 今日（本地 0 点为界）已通过送达验证（IMAP 命中）的收件人数。口径与统计页"今日"柱一致：`recipients.status='verified' AND verified_at` 落在今天本地日。在 BCC 有验证模式下要等 IMAP 命中后才计入。 |
| **已送达** | 绿底 | 累计已通过送达验证的批次数 |
| **未送达/失败** | 红底 | 累计未通过送达验证的批次数 / SMTP 直接失败的批次数。中间是斜杠分隔 |

> 💡 "今日已发"卡片读的是 `recipients` 表，跟统计页"今日"柱用同一个聚合（`BatchStatsRepository.CountTodayVerified`）。如果要看"今天 SMTP 200 OK 但还没等到 IMAP 命中"的实时进度，看下面"账号配额"行（按 `senders.sent_today`）和"当前批次: N 封 BCC"。

### 当前账号信息（卡片下方一行）

| 字段 | 含义 |
|---|---|
| 账号配额 | 当前选中账号的 `已发 / 配额`（如 `100 / 350`） |
| 冷却 | 冷却剩余时间，如 `无` / `12 min` |
| 状态 | `运行中` / `冷却中` / `已封禁` 等 |
| 下一批 | "下一批约 10min 后发送 (间隔)" 或 "等待窗口 (直到 22:00)" |

下方有个进度条（绿色 = 配额已用比例），再下面是"当前批次: 20 封 BCC" 表示正在/即将发送的批次大小。

## 3. 日志

实时日志流，**追加在最底部**，自带颜色和符号。

### 时间格式

`HH:mm:ss`（本地时间）。

### 符号

| 符号 | 颜色 | 含义 |
|---|---|---|
| `✓` | 绿 | 成功（已送达） |
| `⏳` | 蓝 | 等待 / 进行中 |
| `✗` | 红 | 失败 |
| `⚠` | 黄 | 警告（如配置异常） |
| `ℹ` | 灰 | 普通信息 |

### 典型日志条目

```
12:04  ·   下一批约 10min 后发送 (间隔)
12:04  ⏳ 等待验证中 (…0553)
12:04  ✓   发送 20 封 BCC + 验证 (…0553)，最长 5min 验证
11:57  ✓   已验证 (…a5e4)，用时 178s
11:57  ·   [11:57:40] [verified] batch=2026-09-28-004-a5e4 (IMAP 命中)
11:54  ·   下一批约 10min 后发送 (间隔)
11:54  ⏳ 等待验证中 (…a5e4)
11:54  ✓   发送 20 封 BCC + 验证 (…a5e4)，最长 5min 验证
```

日志**仅保留在内存里** —— 关闭窗口/重启后会清空。如需长期日志，看下面"日志文件"。

### 滚动行为

日志会自动滚动到底部跟随最新条目。如果你手动向上滚动查看历史，自动滚动会暂停 5 秒，5 秒后恢复自动滚动。

## 4. 日志文件

每天一份，写到 `<db 父目录>/logs/mailbot-yyyy-MM-dd.log`。

- 格式：`[yyyy-MM-dd HH:mm:ss.fff] [LEVEL] [account=邮箱] 消息`
- LEVEL：`INFO` / `PENDING` / `SUCCESS` / `WARNING` / `ERROR`
- 线程安全（多 Worker 并发写）。

示例：

```
[2026-09-28 12:04:01.234] [INFO] [account=sender@example.com] SendEngine 启动
[2026-09-28 12:04:01.345] [PENDING] 等待下一批次
[2026-09-28 12:04:11.456] [SUCCESS] 发送成功 batch=2026-09-28-005-0553 recipients=20
```

> ⚠️ 日志文件**不轮转**（不会自动删除老文件）。如果 MailBot 长时间运行，建议偶尔归档/清理。

## 5. 托盘和单实例

### 系统托盘

启动后系统托盘（屏幕右下角的紫色信封图标）会出现 MailBot。

右键菜单：

- **显示主窗口** —— 恢复主窗口
- **退出** —— 真正退出应用

双击托盘图标 = 显示主窗口。

### 关闭主窗口

点主窗口右上角 ✕ → 弹窗：

> 关闭 MailBot 时希望如何处理？
>
> - **是** = 最小化到托盘，后台继续运行
> - **否** = 真正退出应用

> 💡 选择"否"会走 `app.ExitApp()`，引擎和验证 Worker 都会优雅停止；选择"是"则窗口隐藏，引擎继续在后台跑。

### 单实例

启动第二份 MailBot.exe：

- 第一实例已在运行 → 第二进程通过命名管道 `MailBot.ShowCommand.v1` 通知第一实例"显示主窗口"，然后自己退出。
- 第一实例已僵死 → 第二进程检测失败也会退出（不强行接管，避免数据冲突）。

> ⚠️ 如果第一实例完全崩溃（Mutex 仍残留但进程已死），第二实例会**等 Mutex 释放**或**直接退出**。可重启机器或用任务管理器确认无残留进程后再启动。
