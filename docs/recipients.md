# 收件人管理

所有收件人数据存在本地 SQLite `recipients` 表里，UI 通过 **收件人** 页管理。

![收件人页](images/recipients.png)

---

## 1. 状态机

每个收件人有 7 种状态（与代码里的 `RecipientStatus` 常量一一对应）：

| 状态 | DB 取值 | 含义 | 进入条件 |
|---|---|---|---|
| **待发送** | `pending` | 在主循环的"待取批次"队列里 | 初始 / 上一批被判定失败回退 / 手动重置 |
| **已发送** | `sent` | SMTP 返回 250 OK，尚未完成送达验证 | 发送器成功投递后立即写入（**仅真实验证模式**会停在这里） |
| **验证中** | `unverified` | 已发出，等待 IMAP 验证命中 | 进入批次发送时标记，分配 `batch_id` |
| **已送达** | `verified` | IMAP 中找到 `From` 匹配的邮件 | 验证 Worker 命中；**无验证模式下 SMTP 成功即直接落此状态** |
| **未确认** | `unconfirmed` | 验证超时仍未命中 | 验证轮询达上限仍未命中；带冷却时间后重回队列 |
| **失败** | `failed` | SMTP 返回失败 | SMTP 发送抛错（可重试） |
| **已屏蔽** | `blocked` | 永久跳过 | 通常由编辑对话框手工标记 |

> 💡 "已送达" 不是"收件人已读"，只是"邮件被收件方邮件服务器接收"。未读/退订/拒收都不影响状态。

## 2. 导入

### 文件要求

- 支持 **Excel（.xlsx）** 和 **CSV（.csv）**。
- **编码自动识别**：
  - 含 BOM `EF BB BF` → UTF-8
  - 含 BOM `FF FE` → UTF-16 LE
  - 含 BOM `FE FF` → UTF-16 BE
  - 其他 → 按 UTF-8 尝试
- **表头识别**：首行如果包含 `@` 字符，视为**无表头**（整行就是数据）；否则视为表头，需要有 `email` 列。

### 列要求

- 必须有一列叫 `email`（大小写不敏感）。
- 其他列会被忽略。
- 邮箱格式会被校验，格式无效的行会被跳过并提示。

### 分隔符切分

一格里可以放多个邮箱，也可以夹杂姓名/备注。导入时按以下分隔符切分，逐段校验：

```
;  ；  ,  ，  、  空格  Tab  换行
```

片段首尾的 `。 ． . 、 , ， ; ； ! ！ ? ？` 会被剥掉（应对中文句尾的"。"）。邮箱统一转小写存储。

| 单元格内容 | 导入结果 |
|---|---|
| `alice@x.com;` | `alice@x.com`（尾部多余分号被忽略） |
| `a@x.com;b@x.com,c@x.com` | 3 条 |
| `alice@x.com;待跟进` | 1 条，备注静默丢弃 |
| `张三 zhangsan@x.com` | 1 条，姓名静默丢弃 |
| `备注;张三;` | 0 条，记为错误行并提示行号 |

**行级规则**：一整行只要能切出**至少一个**合法邮箱，整行就通过，中间无效片段静默丢弃；一个都切不出来才报错。这样空行、"整行都是备注"仍会报错帮你定位行号，而混合内容不会污染错误列表。

> ⚠️ CSV 里用半角逗号分隔多个邮箱时要用引号包起来（`"a@x.com;b@x.com,c@x.com"`），否则逗号会先被 CSV 解析器当成列分隔符。用分号或换行分隔则不需要引号。

### 示例 CSV（最小可用）

```csv
email
alice@example.com
bob@example.com
carol@example.com
```

### 示例 Excel

| email |
|---|
| alice@example.com |
| bob@example.com |

### 操作

收件人页 → 点 **导入 Excel/CSV** → 选择文件 → 导入完成会弹出统计（成功 N 条 / 跳过 M 条）。

> ⚠️ 重复邮箱会被跳过（按 `email` + `source_file` 联合去重，同一邮箱从不同文件导入会各存一条）。如果你想覆盖现有状态，请先在 **删除选中** 中清掉旧记录再导入。

## 3. 导出

点 **导出结果** → 选择保存路径。

- 输出 **UTF-8 with BOM** 的 CSV —— 用 Excel 打开中文不乱码。
- 包含所有列：`email` / `status` / `sent_at` / `error_message` / `attempt_count` / `last_attempt_at` / `batch_id` / `verified_at` / `source_file`。
- 适合做备份或交给其他工具处理。

## 4. 列表操作

### 分页

- 默认 **每页 50 条**。
- 底部翻页控件：**上一页** / **下一页** + 当前页码 + 总页数。

### 状态筛选

顶部下拉框：

- **全部** —— 不筛选
- **待发送** —— 状态 = pending
- **已发送** —— 状态 = sent
- **已送达** —— 状态 = verified
- **验证中** —— 状态 = unverified
- **失败** —— 状态 = failed
- **已屏蔽** —— 状态 = blocked
- **未确认** —— 状态 = unconfirmed

切换筛选后"当前筛选"标签会显示该状态下的总数，已选计数按筛选后范围统计。

### 关键字查询

筛选下拉旁边一个输入框 + 两个按钮：

- **输入框** —— 默认按邮箱子串过滤（大小写不敏感）。如果输入的文本看起来像批次号（含 `-` 且含数字，如 `2026-09-29-001-a3f4`），则自动按批次号精确匹配。
  - 输入 `gmail` / `alice` / `@example.com` → 邮箱子串查。
  - 输入 `2026-09-29-001-a3f4` / `batch-001` → 批次号精确查。
- **搜索** 按钮 —— 执行查询。
- **清空** 按钮 —— 清空输入框并跳回第 1 页。
- 在输入框里按 **回车** 等同于点搜索。

> ⚠️ 批次号采用精确匹配，避免输入 `29` 误中 `2026-09-29-001-a3f4` 之类的子串。
>
> 💡 派发规则倾向邮箱：日常输入 `alice` / `gmail` 等都按邮箱查，只有视觉上像 `YYYY-MM-DD-NNN-XXXX` 这种结构时才走批次号。

查询可与状态筛选叠加（WHERE AND），底部计数与"当前筛选"标签会反映合并后的结果。

### 选择与编辑

- **全选** —— 选中**当前筛选**下所有页的所有行（跨页勾选，按"已勾选: N 条"计数）。
- **重置选中** —— 清掉所有勾选。
- **删除选中** —— 删除已勾选的行（**不可恢复**，会弹确认）。
- **编辑** —— 修改**高亮选中**行的邮箱与状态，一次一条。
- **清空所有**（红色按钮）—— 删除收件人表的**全部记录**，不受筛选、分页、勾选影响。

**清空所有**是不可恢复操作，执行前弹二次确认，标题为"清空所有收件人 - 二次确认"，正文报出**整表实际条数**（不是当前筛选后的条数），并提示先导出备份。表为空时直接提示"无需清空"，不弹确认框。

> 💡 勾选框（跨页批量）和高亮选中（编辑用）是两套独立状态，可以勾 10 行、只编辑高亮的那 1 行。

**编辑操作**：单击选中一行 → 点工具栏 **编辑**，或直接**双击该行**。对话框里：

- **邮箱** —— 自动转小写；格式校验与导入用的是同一个判定函数。
- **状态** —— 7 种状态全部可选，显示中文、存英文值。

保存时如果新邮箱在同一来源文件下已存在，会提示"邮箱已存在"并拒绝保存（对应数据库的 `UNIQUE(email, source_file)` 约束）。

> ⚠️ 手工改状态不受状态机约束。比如把已发送的行改回待发送，下次主循环会重新发一遍；改状态只影响列表显示和"重置/发送"的取数逻辑，不会清理 `sent_at` / `attempt_count` 等历史字段。要干净地重发请用 **重置选中**。

### 列说明

| 列 | 含义 |
|---|---|
| `#` | 行号（在当前筛选+分页内的序号） |
| 选择 | 勾选框 |
| 邮箱 | 收件人邮箱 |
| 批次号 | 该收件人所属批次（`YYYY-MM-DD-NNN-XXXX`）。pending 状态此列为空 |
| 发送次数 | `attempt_count`，失败重试会递增；用于直观看到哪些行被反复尝试 |
| 最后活动 | `verified_at ?? last_attempt_at`，送达时间优先；空表示该收件人从未被尝试过 |
| 状态 | 7 种状态的中文标签，映射见 `RecipientStatusToTextConverter` |
| 错误 | 失败原因（如 `SMTP 535 Authentication failed`） |

## 5. 状态流转细节

```
                导入 / 重置
                   │
                   ▼
              ┌──────────┐
              │ 待发送   │◄──────────────┐
              └────┬─────┘               │
                   │ 主循环取到批次       │ 未确认（冷却结束）
        ┌──────────┴──────────┐        │ / 失败重试
        ▼                     ▼        │
  ┌──────────┐         ┌──────────┐   │
  │  已发送  │         │   失败   │───┘
  └────┬─────┘         └──────────┘
       │ SMTP 250 OK
       ▼
  ┌──────────┐
  │ 验证中   │
  └────┬─────┘
       │
       ├──── IMAP 命中 ────►┌──────────┐
       │                    │  已送达  │（终态）
       │                    └──────────┘
       ▼
  ┌──────────┐
  │  未确认  │──── 冷却结束 ──► 回到待发送
  └──────────┘

  任意状态 ──编辑对话框──► 任意状态（可手工标为 已屏蔽）
```

- "已送达" 是终态。
- "失败" 会被主循环重新取（直到达到 `max_send_attempts`，默认 3）。
- "未确认" 会写 `pending_retry_at` 冷却时间，冷却结束才回到待发送。
- "待发送" 进入批次时分配一个 `batch_id`（格式 `YYYY-MM-DD-NNN-XXXX`，XXXX 是 GUID 前 4 字符），便于追溯。
- 编辑对话框可以跳过上表任意转换，详见 [§4 编辑](#选择与编辑) 的警告。

> 💡 **无验证模式走捷径**：没配验证邮箱时，`待发送` → SMTP 成功后**直接落「已送达」**，不经过「已发送 / 验证中 / 未确认」这几步，也不分配 `batch_id`（所以批次号列为空）。队列照常推进到下一批，不存在等待验证导致的停顿。

## 6. 数据库存储位置

收件人表存在 `recipients`（SQLite），路径见 [README.md](../README.md) "运维与配置" 一节。常用查询示例：

```sql
-- 统计各状态数量
SELECT status, COUNT(*) FROM recipients GROUP BY status;

-- 查最近 24 小时新导入的收件人
SELECT * FROM recipients ORDER BY id DESC LIMIT 100;

-- 查某个批次的所有收件人
SELECT * FROM recipients WHERE batch_id = '2026-09-28-001-a3f4';
```

> ⚠️ 直接改数据库可绕过 UI 校验（如状态机），但不推荐——状态/批次不匹配会让验证 Worker 表现异常。收件人页的 **编辑** 按钮会做邮箱查重，但同样不约束状态流转。
>
> ⚠️ **清空所有** 只删 `recipients` 表，不动发件账号、模板和调度配置。删除后只能靠再次导入恢复，所以务必先 **导出结果** 备份。

### 唯一约束

```sql
UNIQUE(email, source_file)
```

同一邮箱从**不同来源文件**导入会各存一条独立记录。所以查重、编辑保存都必须带 `source_file` 参与判断，只按 email 判重会误报。
